# `src/` build notes

The vendored Hera C++ sources live unmodified under [`src/hera/`](hera/),
kept byte-identical to upstream
(<https://github.com/astamm/hera>, `r-compatibility` branch). Upstream headers
use angle-bracket includes such as `#include <hera/common.h>`, which assume an
include root pointing at the directory *above* `hera/`. Rather than editing the
vendored sources (which would break alignment with upstream), the build
generates an alias layer. This page explains how that works.

## Why `src/Makevars` is not tracked

`src/Makevars` is a **build artifact** generated by `./configure` from
[`src/Makevars.in`](Makevars.in). It is in `.gitignore` and must not be edited
by hand — edit `Makevars.in` instead.

Context: the vendored `hera` sources cannot be found from the R package tree
without an `-I` pointing at `inst/include` (where the alias headers live). In a
plain-`Makevars` package, R leaves `$(srcdir)`, `$(top_srcdir)` and
`$(top_builddir)` **empty**, so the absolute path cannot be written directly in
`Makevars`. That is why a `configure` script is used: R runs it with
`abs_srcdir` set, and it bakes the absolute include path into the generated
`src/Makevars`.

## The generate-on-install flow

```
R CMD INSTALL / R CMD check
        │
        ▼
configure ( / configure.win )                ← abs_srcdir is defined here
  1. mirror src/hera/** → inst/include/hera/** as <forwarding headers>
     (each one just #includes the real vendored file back in src/hera/)
  2. write src/Makevars from src/Makevars.in
     (PKG_CPPFLAGS = -I"<abs_srcdir>/inst/include" -DFOR_R_TDA -DNO_LEGACY_NONAPI)
        │
        ▼
compile src/*.cpp
  <hera/...> now resolves via -I → inst/include/hera/** → src/hera/**
        │
        ▼
cleanup ( / cleanup.win )                    ← reverses configure's side effects
  rm src/Makevars  and  rm -rf inst/include/
```

### What each piece does

- **`src/Makevars.in`** — the committed template. `configure` substitutes
  `@INCLUDE_FLAG@` with the absolute `-I` to `inst/include`, and also sets two
  compile-time flags:
  - `-DFOR_R_TDA` — hera's own upstream hook that suppresses the
    `std::cerr`/`std::cout` diagnostics on its error/debug branches (gated with
    `#ifndef FOR_R_TDA`, see e.g. `hera/bottleneck/bound_match.hpp`). This
    satifies R's requirement that compiled code not write to stdout/stderr.
  - `-DNO_LEGACY_NONAPI` — required to comply with the modern R API.
- **`configure` / `configure.win`** — generate the alias layer and `src/Makevars`.
- **`cleanup` / `cleanup.win`** — required by `R CMD check` to reverse
  `configure`'s side effects. R invokes them automatically after installing.

## It's all derived from upstream

The only things generated are the tiny forwarding headers (which re-include the
real files) and `src/Makevars`. Because the forwarding headers reference the
real vendored files by relative path back into `src/hera/`, the vendored tree
remains the single source of truth: to refresh hera, replace `src/hera/**` and
nothing else needs to change.
